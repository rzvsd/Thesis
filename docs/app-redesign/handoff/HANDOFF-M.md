## For the device pass (CI-only code paths, not provable in the harness) — WP-INT: treat the first item as a gate

- **Gate:** the report WebView (an `AndroidView`; shared elements do not support View interop in the overlay). On the way in it is never visible in the overlay (content alpha 0 until the bounds settle, then a 150 ms fade in place), so a blank WebView in the overlay cannot show. On the way back it is drawn in the overlay at fading alpha for the first ~72 ms of the 240 ms shrink. Check on a phone: no flash or blank frame when a History/Research row opens its report and when back closes it, and the WebView survives (no reload when the report is reopened from the stack, scroll kept). If the way back flickers, hold the report content at alpha 0 on the way back too (`ReportBaseLayer`, `transforming && exiting` branch).
- The tab layer follows the navigator from a `LaunchedEffect` (`SeekableTransitionState.animateTo`), one frame after the navigator moves; the report base layer follows the same `TabSeek.shown`, so the two layers stay in step; the bottom bar and the status bar still follow the navigator (one frame earlier, as in PR-2).
