1. `ui/shell/ShellDestinations.kt` (Destination.Inbox): pass the new, defaulted InboxScreen parameters:
   - `isRefreshing = state.isInboxRefreshing`, and `isLoading` = "first load not answered yet". Without it, the skeleton shows only while refreshing with no alerts.
   - `lastInboxVisitAtMs = state.lastInboxVisitAtMs.takeIf { it > 0L }`, `onMarkAllSeen = actions::onMarkInboxSeen`. (UiState keeps 0 for "never"; the screen also treats values <= 0 as no visit.)
   - `onOpenName = actions::onOpenName`, `onOpenWarRoom = actions::onOpenWarRoom`, and `onOpenNameAtChanges` (see 6).
   - `snackbarHostState` = the shell's host, so the Undo snackbar rides the bottom bar like every other snackbar. Without it the screen draws its own host above `padding`'s bottom.
   - `refreshError` = a failed reload while alerts are shown (see 4).

   Reason: 5.21 asks for the "new since your last visit" lede, Mark all as seen, drift to Name, War Room routing and pull to refresh. All of them are already implemented and tested behind these parameters.
2. `ThesisApp.kt` / `ShellDestinations.kt` (Destination.MacroStress): call `MacroStressScreen(current, history, selectedRangeDays, sentimentError, onSelectRange, onBack, padding, refreshing = state.isMacroRefreshing, onRefresh = actions::onRefreshMacro)` directly, then drop `platform.macroStressDashboard` and the `MacroStressDashboardScreen` wrapper. The wrapper is kept only so ThesisApp compiles unchanged. Reason: the file is no longer Android-only. The shell can compose it in the harness, and padding and refresh are wired.
3. `ui/shell/ThesisShell.kt` `rootRefreshing`: return false for `Destination.Inbox`, which removes the interim hairline under the root bar. Reason: the Inbox's `ThesisRefreshBox` draws its own travelling hairline while refreshing. Two infinite animations on screen break 4.3.10.
4. `MainViewModel` / `UiState`: split `inboxError` into a load error (list fetch) and action errors (mute, feedback, preferences). Then pass the load error as `inboxError`/`refreshError`, and keep action errors on the snackbar only. Reason: 5.21, "action errors as snackbar only (never wipe the list)". The screen already never replaces a loaded list. Today it cannot tell a failed refresh from a failed mute, so with alerts shown it shows no banner for `inboxError`: a failed pull-to-refresh with alerts loaded gives no feedback at all until this lands (required).
   Also give each reported error a key that changes every time (a counter in UiState, for example `inboxErrorSeq`) and pass it as `InboxScreen(inboxErrorKey = ...)`. `muteAlert` does not clear `inboxError` before it runs, so a second failure with the same message is not a new value; the screen restores a refused quiet when `inboxError` or `inboxErrorKey` changes, so without the key a second identical mute failure leaves the row hidden.
5. `MainViewModel.muteAlert` / `onSetNotificationPreference`: when called from the Inbox, do not post a success snackbar ("Quieted ..."). The Inbox has already shown "Alerts like this are quiet for 24 hours" with Undo, and calls the ViewModel only once that snackbar goes without Undo. Keep the failure snackbar. Reason: one message per action.
6. `ui/navigation` (Destination.Name) + `ShellActions`: add an anchor, for example `Destination.Name(ticker, anchor = "since-last-report")`, and an action `onOpenNameAtChanges(ticker)` for the Inbox's `onOpenNameAtChanges`. Reason: 5.21.5, "thesis_drift alerts open Name at its 'Since the last report' block". Until then the Inbox falls back to `onOpenName(ticker)` (Name at the top), then to `onOpenAlert`.
