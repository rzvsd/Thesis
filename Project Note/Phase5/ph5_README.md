# Thesis - Phase 5

**"From research tool to active intelligence engine."**

Phase 5 turns Thesis into a product that watches continuously, speaks only on exception, and helps users improve conviction quality over time.

Phase 1 proved baseline architecture and product viability.  
Phase 2 expanded capability depth and product surface area.  
Phase 3 improved trust, recurrence, and monetization foundations.  
Phase 4 clarified information architecture and made alert history auditable.  
Phase 5 now answers the retention question:

**Why should a user open Thesis on a random Tuesday in July, and why keep paying year-round?**

---

## What Phase 5 Adds

| Capability | Description |
|---|---|
| **Kill-Switch Engine** | Converts thesis narratives into durable falsifiable conditions that are monitored continuously |
| **Thesis Freshness and Decay** | Makes thesis staleness explicit through freshness scoring and review-needed signals |
| **Morning Exception Briefing** | Replaces generic pulse behavior with user-specific "what changed for my names" briefing |
| **Earnings War Room** | Event-windowed pre/live/post earnings workspace with thesis delta handling |
| **Cross-Name Intelligence** | Propagates signals across supplier/competitor/sector relationships in followed names |
| **Conviction Intelligence** | Decision journal, portfolio coherence checks, and opposite-case generation |
| **Scenario Stress Cards** | One-tap scenario-level impact analysis across all followed names |

---

## What Phase 5 Is Not

Phase 5 does not add new platform services.

It is not:

- a brokerage sync phase
- a real-time trading terminal phase
- a social or community phase
- an iOS expansion phase
- an LLM fine-tuning phase
- a visual redesign phase

All Phase 5 UX changes must keep the same Thesis colors, typography, tone, and component style.

If work does not strengthen exception-first thesis intelligence and explainable actionability, it does not belong in Phase 5.
