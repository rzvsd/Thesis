# Thesis - Phase 4

**"Clarity needs a home."**

Phase 4 turns Thesis from a capable product into a clearer operating system.

Phase 1 proved the architecture.
Phase 2 proved the expanded feature set and 3-tab product shell.
Phase 3 proved trust, recurrence, monetization scaffolding, and operational discipline.
Phase 4 must prove that the product map now matches the product intent.

---

## What Phase 4 Adds

| Capability | Description |
|---|---|
| **Mobile IA V2** | Replaces the old 3-tab shell with `Today / Names / Research / Inbox / You` |
| **Names Board** | Followed tickers get a first-class monitoring surface instead of living inside overloaded submodes |
| **Inbox** | Alert history becomes durable, explainable, and reviewable instead of being a transient push experience |
| **Route Clarity** | Push, resume, weekly ritual, and report entry points target explicit screen ownership rules |
| **Copy Discipline** | New IA-level labels and headlines are centralized so tone stays recognizably Thesis |
| **Phase 4 Proof** | Closeout requires local quality evidence now and final Maestro/device proof once hardware is attached |

---

## What Phase 4 Is Not

Phase 4 is not a visual rebrand.

It is not:

- a new palette phase
- a broad product-scope expansion
- a brokerage or holdings phase
- a second notification system
- a permission slip to invent new tuning semantics without a product decision

If work does not improve information placement, alert transparency, route clarity, or operational proof for the new shell, it does not belong in Phase 4.

---

## Phase 4 Strategy

Earlier phases asked:

- can Thesis work?
- can Thesis feel richer?
- can Thesis earn trust and become repeatable?

Phase 4 asks something more operational:

- can the user tell where to act now?
- can the user tell where to inspect evidence?
- can the user tell why an alert fired?
- can the user tell where controls live?

The job is not more product breadth.
The job is better information placement and route certainty.

## Phase 1, 2, and 3 Reference

Phase 4 does not replace earlier phases.

- `Phase1/` remains the source of truth for baseline architecture and doctrine
- `Phase2/` remains the source of truth for the current feature set and original 3-tab redesign history
- `Phase3/` remains the source of truth for trust, monitoring, monetization, and launch-readiness doctrine

Phase 4 is the layer that decides whether all of that existing product power is actually easy to operate.
